# PQL examples (Chapter 8)

Replace `_<TENANT_ID>` with your tenant namespace (e.g. `_acmeretail`).

## Attribute rules

```text
homeAddress.country = "GB"
_<TENANT_ID>.loyalty.tier = "gold"
_<TENANT_ID>.loyalty.tier in ["gold", "platinum"]
_<TENANT_ID>.loyalty.points > 4000
person.name.firstName.startsWith("As")
personalEmail.address.endsWith("@example.com")
_<TENANT_ID>.loyalty.tier = "gold" and not (homeAddress.country = "GB")
```

## Audience membership

```text
inSegment("<AUDIENCE_ID>")
inSegment("<GOLD_AUDIENCE_ID>") and not inSegment("<SUPPRESSION_AUDIENCE_ID>")
```

## Event rules

Event rules generated by the Segment Builder use the `chain(xEvent, timestamp, [...])` form with
`WHAT(...)` (which event) and `WHEN(...)` (time window) clauses. The general shape is:

```text
chain(xEvent, timestamp, [C0: WHAT(eventType.equals("commerce.purchases", false)) WHEN(<= 30 days before now)])
```

Recommended workflow for event logic (avoids syntax mistakes):

1. Build the rule in the Segment Builder UI (e.g. "Event type equals Product Views, in the last 7 days").
2. Save it, then read the generated PQL with `GET /data/core/ups/segment/definitions/<ID>` (`expression.value`).
3. Reuse that expression in your JSON files and pipelines.

## Patterns for common use cases

| Use case | Logic (in words) | Typical method |
| --- | --- | --- |
| Cart abandonment | Added to cart in the last hour AND no purchase since | Streaming |
| Browse abandonment | Viewed product category X 2+ times in 7 days, no purchase | Batch or streaming |
| Lapsed customers | Last purchase more than 180 days ago | Batch (or computed attribute) |
| VIP on site | Profile attribute tier = gold | Edge |
| Suppression | Opted out OR complaint OR employee OR test account | Batch/streaming |
